# 统一获奖导入实现说明

日期：2026-10-29

## 使用流程

1. 在“获奖管理 → 获奖填报”点击“统一导入获奖名单”。
2. 下载统一模板，在第一个工作表“获奖名单”填写数据。第二个工作表为当前账号可填报赛事目录，第三个工作表为填写说明。
3. 上传后点击“匹配赛事并校验”，检查每个赛事的名称、可新增人数、重复和失败人数。年份由系统按当前年份自动确定，页面只读展示，不需要填写。
4. 同年同名赛事会要求明确选择目标赛事；选择应用到该组所有未完成的行，再次校验。
5. 点击“导入可新增的 N 行”。失败行不会写入；已有记录与文件内同团队重复行会跳过。
6. 查看校验失败结果，可定位修改或导出失败名单。失败名单保留赛事名称和原因，不再包含赛事编号、年份填写列；修正后可按当前年份重新上传匹配，同名歧义仍须明确选择。已成功、已跳过的行保留在当前预览，后续提交只处理未完成的行。

单赛事导入仍通过原入口操作，共用同一页面、模板样式、Excel字段解析及获奖校验写入逻辑。

## 模板

列顺序：序号、赛事名称、学号、学生姓名、所属学院、所在专业、参赛项目名称、获奖时间（年/月）、获奖类别、获奖等级、指导教师工号、备注。

- 赛事识别只需填写完整赛事名称，不需要赛事年份和编号。
- 后端按当前年份匹配目录，使用 `Asia/Hong_Kong` 时区（UTC+8），跨年自动切换；不从获奖年月推断年份。旧表格或JSON中的年份、编号字段不会覆盖当前年份规则。
- 每行一名学生，多个赛事可混排，数据区不合并单元格。
- 按表头读取，支持调整列顺序；只读取第一个工作表。空行、示例行不导入，说明边界沿用原规则。
- 学号、教师工号和获奖月份使用文本格式，保留前导零。
- 每批最多5000行，前后端均校验；上传文件与JSON请求上限20MB。前端另限制Excel使用区域不超过10000行。

## 匹配与权限

- 名称在系统当前年份、当前可填报范围内唯一匹配时自动关联；多个候选时返回候选供用户选择，不要求用户填写编号。系统编号仅在候选列表中用于区分同名项。
- 目录下载、预览及提交均限定当年赛事；往年才有的赛事不会自动接收本次统一导入。旧模板或JSON里的年份、编号不参与匹配，也不能将请求改投往年。
- 不做模糊自动归属，也不自动创建赛事。
- 模板目录、匹配候选、预览及提交统一使用获奖填报的 `awardCompetitionScope`，保留院管理员对本管理学院、校级赛事、未绑定学院赛事的既有规则；赛事负责人仅限本人负责赛事。
- 客户端传入的匹配状态、候选、已存在标记不能作为授权依据。服务端重新匹配和校验。
- 预览返回明确的 `comp_id`。提交使用该ID重新检查存在性、名称、当前年份和权限；赛事删除、改名、跨年等导致不一致时该行失败，不能自动改投另一个同名赛事。

## 获奖与事务规则

- 按赛事ID分组后复用 `validateAwardRows`、`writeAwardImportRows`。
- 团队在各自赛事内按项目名称归组，不同赛事的同名项目独立。同一学生可获不同赛事奖项，但同一赛事不能有多条获奖记录。
- 团队类别、等级、时间、教师冲突时该团队整体失败；单个学生身份校验错误仅阻止该行。
- 重复导入不覆盖奖项、成员备注及首次提交人和提交学院。新增成员继续加入原团队。
- 全局报名开关继续生效，检查的是对应目标赛事的审核通过报名；来源、审核状态、指导教师和身份快照沿用单赛事导入规则。
- 提交在事务外解析赛事，进入事务后读取并锁定全局设置，再按赛事ID升序锁定目标赛事并核对归属，最后读取学生及已有获奖进行校验。MySQL可重复读模式下，事务内的首次普通查询必须发生在赛事锁获取之后，以免并发等待后仍使用旧快照。业务校验失败的行返回错误，有效行可写入；数据库写入异常则本次全部写入回滚。
- 成功后清理涉及赛事的获奖缓存及统计缓存。数据仍写入现有获奖表、成员表和教师表，无新增数据库迁移。

## 接口

| 方法与路径 | 用途 |
|---|---|
| `GET /api/award/import/unified/template` | 下载模板及有权限的赛事目录 |
| `POST /api/award/import/unified/preview` | 赛事匹配、获奖校验与逐赛事汇总，不写入 |
| `POST /api/award/import/unified` | 事务内重新校验并导入，返回逐行及逐赛事结果 |

三个接口均经过认证和 `award:import` 权限中间件。预览、提交支持 `{ "rows": [...] }` JSON或包含 `file` 字段的multipart Excel。赛事识别输入为 `comp_name`，`comp_id` 仅用于绑定预览结果或同名项的明确选择；返回的 `comp_year`、`comp_code` 为系统信息，不作为用户填报字段。响应中的 `import_year` 为后端确定的本次导入年份。

结果包含 `rows`、`competitions`、`ready_count`、`success_count`、`existing_count`、`fail_count`、`student_count`、`team_count`、`require_registration`。`team_count` 沿用现有导入的涉及团队数口径，不能视为新建团队数。行的 `match_status` 为 `matched`、`ambiguous` 或 `unmatched`；提交后的 `import_status` 为 `imported`、`existing` 或 `failed`。

## 模板样式修正

修复赛事年份、赛事编号、学号、获奖时间和指导教师工号列样式不一致的问题。原实现在表格样式设置后调用 `SetColStyle`，整列文本样式覆盖了表头加粗/居中及数据区边框。现改为在共用模板布局中先设置文本列默认格式，再应用完整的表头及数据区样式；统一导入不再重复覆盖整列样式。

模板回归在实际xlsx序列化再读取后验证所有12列表头一致，以及数据首尾行的宋体、字号、对齐和黑色边框；同时验证新追加的行仍使用文本格式，保留学号、工号前导零。单赛事模板与解析回归也已通过。移除年份、编号填写列后，模板继续复用这些样式规则。
